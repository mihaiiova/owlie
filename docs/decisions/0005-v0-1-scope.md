# ADR 0005 — Owlie CLI v0.1 scope: YouTube extraction + pipeable DeepSeek processing

- **Status:** Accepted (YouTube transcript mechanism superseded by [ADR 0006](0006-pure-js-youtube-transcripts.md); bounded RSS/Atom `list` superseded by [ADR 0012](0012-rss-atom-cli-listing.md))
- **Date:** 2026-08-19

## Context

The repository is a scaffold: contracts compile, tests pass, and `pnpm check`
is green, but no real extraction or processing exists. Earlier plans
(ADR 0002 and the original `docs/product-scope.md`) described a larger "first
functional CLI" (`list`, `search`, `config`, `--each`, `jsonl`, collections,
and OpenAI + Whisper as functional providers). v0.1 narrows that first
milestone to a small, pipe-first slice.

## Decision

v0.1 is a small, functional, pipeable CLI. The functional commands are:

```text
owlie extract URL
owlie process [FILE] --prompt "..."
owlie doctor
owlie --help
owlie --version
```

- **YouTube — individual videos only.** Recognize and canonicalize supported
  video URLs, resolve a stable `youtube:video:<id>` identity, extract an
  available transcript (via the pure-JS `@hallelx/youtube-transcript` library —
  see ADR 0006), and return a `NormalizedDocument` with video ID, canonical
  URL, transcript language, and whether captions are generated. No playlists
  or channels.
- **DeepSeek — the only functional LLM provider.** Implemented with `ai` and
  `@ai-sdk/deepseek` behind the provider-neutral `ContentProcessor` contract,
  configured explicitly (`DEEPSEEK_API_KEY` is loaded only by the CLI).
- **Pipe-first stream contract.** `stdout = result only`, `stderr =
diagnostics and progress only`, exit codes `0` (success), `1` (error),
  `2` (usage), `3` (not implemented). `process` accepts a positional file,
  `--input FILE`, or stdin and rejects ambiguous multiple inputs.
- **Collections stay unimplemented in v0.1.** Collection contracts remain for
  later adapters, but v0.1 implements no `search`, `--each`, or `owlie run`.
  Bounded RSS/Atom `list` was later made functional by [ADR 0012](0012-rss-atom-cli-listing.md).

Deferred scaffold packages (`adapter-podcast`, `adapter-rss`,
`adapter-reddit`, `provider-openai`, `provider-whisper`) are not deleted, but
documentation must not imply they are functional.

## Consequences

- `docs/`, `README.md`, and the root `AGENTS.md` are realigned to the v0.1
  milestone, with the v0.1 decisions treated as authoritative over older plans.
- The shared core is finalized only to the extent the two real capabilities
  require, and stays provider-neutral.
- OpenAI and Whisper remain non-functional scaffolds; DeepSeek is the only
  live LLM provider in v0.1.
- Deferred capabilities (`search`, `config`, `jsonl`, collections,
  transcription) are documented as scaffold/deferred rather than functional.
  Bounded RSS/Atom `list` is the sole exception (ADR 0012).
