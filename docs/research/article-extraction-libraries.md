# Article-extraction libraries

**Decision:** use **[`@extractus/article-extractor`](https://github.com/extractus/article-extractor)**, called with already-fetched HTML (`extractFromHtml`), rather than its URL-fetching convenience API. It is the best fit for Owlie: it packages Mozilla Readability with LinkeDOM, exposes TypeScript declarations, returns article metadata in addition to body content, and is actively released. Its README documents both URL and raw-HTML entry points and the returned article fields ([API](https://github.com/extractus/article-extractor#usage)); its published manifest declares the `@mozilla/readability` and `linkedom` dependencies and `.d.ts` entry point ([npm manifest](https://registry.npmjs.org/@extractus/article-extractor/latest)). The project has a current v9.0.0 release ([release](https://github.com/extractus/article-extractor/releases/tag/v9.0.0)).

## Constraint and integration

Inspection of `../owlie-app` was limited to observable RSS behavior and declared dependencies: its RSS path parses with `rss-parser`, then makes a direct page fetch and uses a simple HTML-tag-stripping heuristic. Owlie must not reuse that fetch behavior or code.

Owlie's existing [`HttpFetcher` ADR](../decisions/0010-safe-http-fetch-core.md) requires SSRF checks, manually validated/capped redirects, timeout, content-size cap, user agent, and Node 20 native fetch. The adapter should therefore:

1. use `HttpFetcher` to obtain only accepted `text/html`/XHTML responses under its byte cap;
2. decode the bounded body, pass HTML and final (post-redirect) URL to `extractFromHtml`;
3. treat empty/too-short extraction as a normal extraction error; return plain text (or sanitized HTML converted locally), never execute page scripts;
4. **not** call the package's `extract(url)` helper, so the package cannot bypass Owlie's SSRF, redirect, MIME, size, timeout, cancellation, or user-agent policy.

These libraries parse supplied static HTML; none renders client-side JavaScript. Dynamic/article-shell sites consequently need a separate, explicitly scoped browser-rendering feature—not a fallback in the safe core.

## Implementation boundary

Add one adapter-local conversion layer, with fixtures for representative static article pages and failure cases (wrong MIME, capped response, malformed HTML, and no article). Do not add a second network client or let an extractor fetch URLs. Keep package updates reviewed because the recommendation is a supply-chain dependency even though it remains behind Owlie's bounded fetch boundary.

## Residual risks

- Heuristic extractors can select navigation, comments, paywall text, or an incomplete article; quality must be measured on Owlie fixtures before making it default.
- Correct MIME and byte limits protect retrieval, not parser CPU/memory consumption; retain a conservative HTML cap and cancellation boundary.
- Static extraction cannot recover content rendered after JavaScript execution.
